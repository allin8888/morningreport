# 全球市场晨报 · 产品评估报告（产品经理视角）

**评估日期**：2026-10-17（周六） · **评估对象**：「全球市场晨报」产品 = 晨报内容（HTML/MD 报告）+ 生成管线（`morning_brief` 包 + `_build.py`）+ 分发归档（O: 网盘 / 微信推送 / SQLite 沉淀）
**产品定位**：单用户（Jonathan）内部效率工具，工作日 09:15 + 周六特刊定时生成，面向"盘前 3 分钟速读"，非公开 C 端产品。社交互动维度因此天然弱化，文中如实说明。
**结论先行**：产品核心价值成立、内容结构成熟（100/100 校验通过、双源校验铁律已落地）；主要问题集中在 **① 增强注入层有 4 个已验证 UI 缺陷；② 已建成的历史分位（compare）与信号回测（signals）能力未接入每日流水线，处于闲置状态；③ 数据取数依赖 LLM 检索自律，旧闻混入风险无程序化兜底**。优先级建议见文末总表。

## 一、核心功能与用户价值

### 1.1 现状分析
| 模块 | 现状 | 评价 |
|---|---|---|
| 内容覆盖 | 三句速读 + 三大市场（含活跃3/回避2）+ 商品汇率 + 政策 + 外围 + 主线5条 + 日历 | ✅ 覆盖完整，结构经 finalize 强制校验（必保分区缺失即失败） |
| 数据可信 | "2026年"前缀 + 量级区间 + 双源一致 + 待核实标注，写入 prompt 与 config.yaml | ✅ 纪律健全；本次执行中成功剔除 2025 旧闻（沪指 3916 / 恒指 17640 等混入） |
| 历史纵深 | store.py 每日落库 SQLite；compare.py 支持"今日 vs 近20日分位/极值" | ⚠️ 能力已建成但**未接入每日报告**——报告无"历史分位"呈现，sparkline 仅 3 点 |
| 反馈闭环 | signals.py 支持记录活跃/回避方向 + 次日命中率回测 | ⚠️ 已建成但**每日流水线未调用**——方向判断写了却无命中率反馈，无法迭代 |
| 个性化 | 无（所有用户收到同一份；实际单用户） | ⚠️ 无自选股/关注板块/推送分级 |
| 体验断点 | ① 旧闻混入靠模型自律，无代码级拦截；② HTML/MD 一致性靠人工同步；③ 周末特刊口径切换靠 prompt 约定 | ❌→⚠️ 三个断点均有现实风险（本次即有 2025 数据混入检索） |

### 1.2 优化建议
1. **接通 compare.py**：报告新增「指标历史分位」行（今日值在近 20 日的百分位），替代"备注"里的文字描述。
2. **接通 signals.py**：finalize 时自动记录三市场方向研判；每周一报告附「上周方向命中率」。
3. **数据校验代码化**：将 config.yaml 的 calibration 区间从"prompt 约束"升级为"生成后程序化校验"——对最终写入的 5 个指标自动比对区间，越界即拦截并要求复核（区间本身保留人工更新机制）。

### 1.3 新增功能/玩法设想
| 设想 | 说明 |
|---|---|
| A. 历史分位卡 | 每个指标标注"近20日分位 + 极值距离"，盘前判断"贵/便宜" |
| B. 命中率周榜 | 每周一汇总上周活跃/回避方向命中率，驱动 prompt 自优化 |

## 三、界面 UI 与视觉设计

### 3.1 现状分析（含已验证缺陷）
整体：暗色主题（bg #0e1420）、卡片式布局、860px 阅读宽度、760px 响应式断点，方向色遵循涨红跌绿（--up #e23b3b / --down #1f9d63）——**设计基调正确**。但 finalize 增强注入层存在 **4 个已验证缺陷**（证据见附录）：

| # | 缺陷 | 证据 | 严重度 |
|---|---|---|---|
| 1 | `.mb-spark`（指标近况）注入后**无任何 CSS 定义** | HTML 中该类仅出现于第 50 行标记，样式表（第 37-47 行）只定义了 mb-toc/mb-top | ❌ P0 |
| 2 | sparkline 折线**全部硬编码绿色 #16a34a**，无视涨跌方向 | 第 50 行 5 个 polyline 均 stroke="#16a34a"；恒指 +0.43% 亦为绿，违反涨红跌绿 | ❌ P0 |
| 3 | 目录项**倒序**（八→一） | 第 51 行 ol 列表顺序 | ❌ P0 |
| 4 | 目录/按钮为**亮色主题**（白底、#2563eb 链接），与暗色正文冲突 | 第 38-46 行 rgba(255,255,255,.92) 等 | ⚠️ P1 |

其他观察：sparkline 标签为英文键名（hsi/sse/nasdaq/brent/gold）且无数值/日期，信息密度低；`.mb-spark` 被注入在 `.wrap` 容器之外、`<nav>` 之前，布局位置不合理；正文 h1/h2/h3 层级清晰、tabular-nums 数字对齐到位（✅）。

### 3.2 优化建议
1. **P0 三连修**：为 mb-spark 补齐样式（跟随 design tokens）；折线按指标当日涨跌着色（涨 #e23b3b / 跌 #1f9d63）；目录正序。
2. 目录/按钮改用 design tokens（暗色底、--accent 链接色），与正文同源。
3. sparkline 升级为「中文标签 + 当日数值 + 日期」，纵向利用 store.py 的近 20 日序列画 20 点（而非当前 3 点）。
4. 增加主题切换（暗/亮/跟随系统），亮色主题需单独校准 tokens。

### 3.3 新增功能/玩法设想
| 设想 | 说明 |
|---|---|
| I. 20 日走势 sparkline | 用 metrics.db 历史序列，鼠标悬停显示每日数值 |
| J. 深/亮主题切换 | 按钮 + localStorage 记忆；默认跟随系统 |
| K. 指标迷你卡（hero 区） | 页面顶部一行 5 张指标卡：名称/点位/涨跌/迷你走势，替代现有裸 sparkline 条 |

## 四、技术性能与可扩展性

### 4.1 现状分析
| 维度 | 现状 | 评价 |
|---|---|---|
| 架构 | `morning_brief` 包分层清晰：config/prompt/generate_report/validate/archive/store/compare/signals/enhance/index + 11 个测试文件 | ✅ 接缝设计良好，方案B 目标基本达成 |
| 取数 | 每次执行 ~6-8 次 WebSearch，无缓存、无结构化数据源聚合器 | ⚠️ 慢（分钟级）且强依赖检索质量（本次即混入旧闻） |
| 稳定性 | 归档 3 次重试 + 降级 local_only；finalize 校验 100/100 一次通过 | ✅ 降级链完整 |
| 一致性 | HTML/MD 双格式由同一 generation 流程产出，逐条一致 | ✅ 本次两条产物信息一致 |
| 复用性 | config.yaml 集中管理；design tokens 内联于每份 HTML | ⚠️ tokens 未抽成共享文件，与其他报告产品（LLM 定价报告等）风格漂移 |
| 监控 | 无（生成失败/归档失败无告警） | ❌ 定时任务静默失败风险 |

### 4.2 优化建议
1. 抽取共享 design tokens 与注入逻辑为独立模块，供 LLM 定价报告等产品复用，统一视觉语言。
2. 增加运行健康检查：生成耗时、归档状态、校验评分写入日志；连续失败 N 次触发告警。
3. 取数层引入结构化源（如行情 API）作为主源、WebSearch 作为兜底交叉验证，降低对检索的依赖。

### 4.3 新增功能/玩法设想
